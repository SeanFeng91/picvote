# 开发文档：百人级图片/视频投票系统

## 1. 技术选型

| 层级 | 方案 |
| --- | --- |
| 前端 | Next.js App Router，React，移动端与管理端共享业务接口 |
| 部署 | Cloudflare Workers/Pages 体系下部署 Next.js 应用 |
| 数据库 | Cloudflare D1，存储账号、作品、投票、活动配置 |
| 文件存储 | Cloudflare R2，存储图片、视频与压缩预览文件 |
| 实时刷新 | MVP 使用短轮询；如后续需要大屏强实时，再升级 SSE/WebSocket/Durable Object |
| 样式 | Ant Design + 自定义高密度相册布局，移动端和电脑端分别设计信息密度 |

## 3. 数据模型

### 3.1 activities

存储活动实例，第一版可以只有一条活动记录，但仍建议保留该表，方便后续复用。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | text | 活动 ID |
| name | text | 活动名称 |
| status | text | `draft` / `uploading` / `voting` / `closed` / `published` |
| default_vote_quota | integer | 默认票数，初始为 5 |
| allow_self_vote | integer | 是否允许给自己投票 |
| show_public_votes | integer | 展示端是否公开具体票数 |
| upload_ends_at | text | 上传截止时间 |
| vote_ends_at | text | 投票截止时间 |
| created_at | text | 创建时间 |
| updated_at | text | 更新时间 |

### 3.2 users

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | text | 用户 ID |
| employee_no | text | 工号，唯一 |
| display_name | text | 显示名称 |
| role | text | `participant` / `special` / `admin` |
| can_upload | integer | 是否可上传 |
| can_vote | integer | 是否可投票 |
| vote_quota | integer | 个人票数额度，空值使用活动默认值 |
| password_hash | text | 登录凭据哈希 |
| created_at | text | 创建时间 |
| updated_at | text | 更新时间 |

### 3.3 works

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | text | 作品 ID |
| activity_id | text | 活动 ID |
| owner_user_id | text | 上传人 |
| code | text | 作品编号，如 `A023` |
| media_type | text | `image` / `video` |
| title | text | 可选标题 |
| r2_key_original | text | 原始文件 R2 key |
| r2_key_preview | text | 预览文件 R2 key |
| mime_type | text | 文件类型 |
| size_bytes | integer | 文件大小 |
| status | text | `active` / `hidden` / `deleted` / `rejected` |

### 3.4 votes

一票一条记录，便于追溯，也支持同一用户给同一作品投多票。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | text | 投票 ID |
| activity_id | text | 活动 ID |
| voter_user_id | text | 投票人 |
| work_id | text | 作品 ID |
| status | text | `valid` / `void` |
| reason | text | 作废原因 |
| created_at | text | 投票时间 |

### 3.5 audit_logs

记录管理员改配置、作品下架、用户删除、票数调整等关键动作。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | text | 日志 ID |
| actor_user_id | text | 操作人 |
| action | text | 操作类型 |
| target_type | text | 目标类型 |
| target_id | text | 目标 ID |
| payload_json | text | 变更详情 |
| created_at | text | 操作时间 |

### 3.6 upload_sessions

记录图片 30MB / 视频 300MB 的分片上传状态，便于重试和清理。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | text | 上传会话 ID |
| work_draft_id | text | 上传中的作品草稿 ID |
| owner_user_id | text | 上传人 |
| object_key | text | R2 对象 key |
| file_name | text | 原始文件名 |
| media_type | text | `image` / `video` |
| mime_type | text | MIME |
| size_bytes | integer | 文件大小 |
| part_size | integer | 默认 10MiB |
| total_parts | integer | 分片总数 |
| parts_json | text | 已上传分片的 etag / partNumber |
| status | text | `pending` / `uploading` / `completed` / `aborted` / `failed` |
| expires_at | text | 超时清理时间 |

## 6. 关键业务实现

### 6.1 编号生成

- 编号需要在活动内唯一。
- 建议格式为 `A001` 到 `A999`。
- 新作品创建时在事务中分配下一个编号。
- 用户删除后重新上传可以生成新编号，避免旧编号在现场传播后混淆。

### 6.2 每人一个作品

上传接口必须在数据库层和业务层双重保证：

- 查询当前用户是否已有 `active` 或 `hidden` 状态作品。
- 如果存在，返回“请先删除原作品”。
- 允许同一用户存在历史 `deleted` 作品。

### 6.3 投票扣减

投票接口流程：

1. 校验登录态。
2. 校验活动处于投票中。
3. 校验用户 `can_vote`。
4. 查询用户票数额度。
5. 统计该用户当前有效投票数。
6. 若剩余票数不足，拒绝。
7. 校验作品可投。
8. 写入 vote 记录。
9. 更新作品 `vote_count_cache`。

并发处理必须使用事务，避免重复点击导致超投。

### 6.4 作品删除后的票数处理

用户删除作品或管理员下架作品后：

- 将作品状态改为 `deleted` 或 `hidden`。
- 将该作品对应的有效票标记为 `void`。
- 重新计算作品票数缓存。
- 排名接口只统计 `valid` 且作品状态为 `active` 的票。

### 6.5 实时数据

MVP 推荐使用短轮询：

- 用户相册：投票后立即乐观更新，后台每 10-15 秒刷新。
- 管理排名：每 2-5 秒刷新。
- 大屏展示：每 2-5 秒刷新。

百人级规模下短轮询实现简单、稳定、可排查。若现场需要更强实时感，再升级为推送通道。

## 8. 部署配置

平台参考：

- Cloudflare Next.js 部署：`https://developers.cloudflare.com/workers/frameworks/framework-guides/nextjs/`
- Cloudflare D1：`https://developers.cloudflare.com/d1/`
- Cloudflare R2 Workers API：`https://developers.cloudflare.com/r2/get-started/workers-api/`
- Cloudflare Workers bindings：`https://developers.cloudflare.com/workers/configuration/bindings/`

### 8.1 环境变量与绑定

```text
SESSION_SECRET=
ADMIN_BOOTSTRAP_EMPLOYEE_NO=
MEDIA_BUCKET=
DB=
```

Cloudflare 配置中需要绑定：

- D1 database binding：`DB`
- R2 bucket binding：`MEDIA_BUCKET`

### 8.2 部署流程

1. 创建 Cloudflare D1 数据库。
2. 创建 Cloudflare R2 bucket。
3. 配置本地 `.env.local` 和 Cloudflare 环境变量。
4. 执行 D1 migrations。
5. 初始化管理员账号。
6. 部署 Next.js 应用。
7. 用真实手机访问生产域名验证上传、投票、排名。

## 9. 测试清单

### 单元测试

- 编号生成唯一。
- 每人 1 个有效作品约束。
- 投票额度计算。
- 作品删除后票数作废。
- 管理员修改票数后剩余票数重算。

### 接口测试

- 未登录无法上传和投票。
- 禁止上传账号无法上传。
- 禁止投票账号无法投票。
- 连续投同一作品可正常扣票。
- 超出额度投票被拒绝。
- 已删除作品不可投票。

### 端到端测试

- 普通用户完整流程：登录、上传、查看编号、投票、查看剩余票。
- 替换作品流程：删除、重新上传、新编号。
- 管理员流程：导入账号、修改票数、查看排名、隐藏作品。
- 手机端拍照上传。
- 手机端相册读取上传。
- 电脑端管理后台高频刷新。

## 10. 开发优先级

1. 数据模型、登录、权限。
2. 上传与 R2 存储。
3. 作品编号和相册。
4. 投票与票数扣减。
5. 管理排名与账号配置。
6. 响应式交互打磨。
7. Cloudflare 生产部署。
8. 活动前压测与操作手册。
