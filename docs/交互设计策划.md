# 交互设计策划：图片/视频作品投票系统

## 1. 设计目标

系统服务的是活动现场和短周期内部评选，交互设计要优先保证“快、清楚、可控”。

- 手机端：参与者通常站着操作，目标是 30 秒内完成登录或投票，1 分钟内完成上传。
- 电脑端：管理员需要高密度查看数据，快速发现异常，适合表格、筛选、排名和状态控制。
- 展示端：服务现场氛围，适合大字号、稳定排名、低干扰动画。

## 2. 体验原则

1. 先显示当前可做什么，再显示活动说明。
2. 所有关键状态都要可见：剩余票数、我的作品编号、上传状态、活动阶段。
3. 作品编号是核心识别物，要在相册卡片、详情页、分享文案、管理后台中保持一致。
4. 手机端按钮不小于 44px，高频操作靠底部固定区完成。
5. 管理端减少装饰，优先表格密度、筛选、状态标签和批量操作。
6. 任何不可逆操作必须二次确认，尤其是删除作品、下架作品、关闭投票。

## 3. 信息架构

```text
用户端
  登录
  首页
    我的作品
    我的票数
    进入相册
  上传/替换
  相册

    作品列表
    作品详情
  我的投票

管理端
  管理概览
  实时排名
  账号配置
  作品管理

展示端

```

## 4. 用户端流程

### 4.1 登录流程

目标：减少现场解释成本。

1. 用户打开链接。
2. 输入工号和活动口令。
3. 系统校验账号是否存在。
4. 登录成功进入首页。
5. 如果账号无权限，显示原因和联系管理员提示。

页面要点：

- 输入框优先数字键盘。
- 登录按钮在首屏可见。
- 错误提示直接说明“工号不存在 / 暂未开放投票 / 暂未开放上传”。

### 4.2 首页流程

首页不是宣传页，而是任务面板。

首屏需要包含：

- 活动状态。
- 我的剩余票数。
- 我的作品编号；如果未上传，则显示上传入口。
- 进入相册的主按钮。
- 若活动未开始或已结束，明确显示当前不能操作的原因。

手机端建议布局：

```text
[活动状态]
[我的作品编号 / 未上传提示]
[剩余票数 5]
[上传作品] [进入相册]
[我的投票记录]
```

### 4.3 上传流程

目标：兼容手机拍摄与相册选择。

状态 1：没有作品

- 显示两个主要入口：拍照/录像、从相册选择。
- 文件选择后进入预览确认。
- 确认上传后显示进度。
- 上传成功显示作品编号。

状态 2：已有作品

- 展示当前作品缩略图、编号、票数状态。
- 上传入口置灰。
- 提供“删除并重新上传”。
- 删除前确认：“删除后当前作品将从相册移除，已获得票数不再计入排名。”

状态 3：上传失败

- 保留本地预览。
- 提供重试。
- 明确失败原因：文件太大、格式不支持、网络异常、权限不足。

### 4.4 相册流程

目标：让用户能按编号快速找到作品，也能自然浏览投票。

核心元素：

- 顶部固定搜索框：输入编号如 `A023`。
- 分类切换：全部、图片、视频、我投过。
- 作品卡片：编号、缩略图、当前得票、投票按钮。
- 剩余票数固定在底部或顶部。

投票交互：

- 卡片上显示向上箭头按钮，点击投 1 票。
- 详情页提供更明确的投票控件，可一次选择 1-5 票中的可用数量。
- 投票成功后按钮反馈，并更新剩余票数。
- 剩余票数为 0 时，投票按钮不可用，并显示已用完。

### 4.5 作品详情流程

详情页适合确认作品内容后投票。

内容顺序：

1. 作品媒体。
2. 作品编号。
3. 上传人显示名或匿名规则。
4. 当前票数。
5. 投票控件。
6. 返回相册。

视频作品：

- 默认展示封面。
- 点击播放。
- 移动端避免自动播放。

## 5. 管理端流程

### 5.1 管理概览

首屏应同时展示：

- 活动阶段控制。
- 已上传作品数。
- 已投票人数。
- 总有效票数。
- 异常提示：上传失败、隐藏作品、无权限尝试、超投拦截。
- Top 排名。

建议电脑端采用两栏：

- 左侧：活动状态、关键指标、阶段操作。
- 右侧：实时排名和作品流。

### 5.2 账号配置

管理员高频任务是导入和修正账号。

功能：

- 批量导入 CSV。
- 搜索工号。
- 编辑单个账号。
- 批量开启/关闭上传权限。
- 批量开启/关闭投票权限。
- 修改票数额度。

表格字段：

- 工号。
- 姓名/昵称。
- 角色。
- 上传权限。
- 投票权限。
- 票数额度。
- 已投票数。
- 作品编号。
- 最后操作时间。

### 5.3 作品管理

管理端作品列表用于快速处理争议。

筛选：

- 全部。
- 图片。
- 视频。
- 正常。
- 已隐藏。
- 用户已删除。

操作：

- 查看大图/视频。
- 隐藏作品。
- 恢复作品。
- 查看投票来源。
- 复制作品编号。

### 5.4 实时排名

排名页面要稳定，不应因为刷新造成强烈跳动。

设计建议：

- 前 3 名突出显示。
- 其余排名使用紧凑列表。
- 同票时显示相同票数但排名顺序稳定。
- 支持隐藏票数，只展示排名。
- 支持投屏模式，放大编号与缩略图。

## 6. 响应式策略

### 手机端

- 底部导航：我的、相册、上传、投票记录。
- 上传和投票按钮固定在易触达区域。
- 作品卡片使用单列或双列瀑布流，默认双列。
- 搜索编号始终在顶部。
- 视频卡片显示播放标识，但不自动播放。

### 桌面端

- 管理后台使用左侧导航 + 主内容区。
- 表格支持筛选、排序、固定表头。
- 相册可以使用 4-6 列网格。
- 排名与作品详情可以并排查看。

### 大屏端

- 16:9 优先。
- 只保留排名、编号、缩略图、票数或排名变化。
- 减少小字和复杂筛选。
- 自动刷新但避免闪烁。

## 7. 关键状态设计

| 场景 | 设计处理 |
| --- | --- |
| 活动未开始 | 显示倒计时或“暂未开始”，隐藏上传/投票主按钮 |
| 上传中 | 显示进度条和不要关闭页面提示 |
| 上传成功 | 强调作品编号，提供复制编号 |
| 已有作品 | 显示当前作品，上传按钮替换为删除重传 |
| 票数不足 | 投票按钮禁用，显示已用完 |
| 投票成功 | 剩余票数即时变化，作品票数轻微动效 |
| 作品被下架 | 用户端隐藏，管理端保留记录 |
| 网络错误 | 保留当前操作上下文，提供重试 |

## 8. 文案风格

文案要短，现场可读。

- “你的作品编号：A023”
- “剩余 3 票”
- “投 1 票”
- “票数已用完”
- “删除后当前作品将不再参与排名”
- “活动已截止，结果以管理员公示为准”

避免长段说明，把规则放在折叠说明或活动页底部。

## 9. 可选设计方向

### 方向 A：活动工具型

适合内部会议或正式评选。视觉克制，强调效率、清楚和可信。

### 方向 B：现场氛围型

适合年会、摄影赛、趣味活动。相册更视觉化，排名有轻量动画。

### 方向 C：评委控制型

适合有特殊账号和权重票的场景。强调不同角色票数、后台审计和结果可解释。

建议 MVP 先采用方向 A，展示端吸收方向 B 的氛围感。

## 10. 原型优先级

第一轮高保真原型建议覆盖：

1. 手机登录。
2. 手机首页。
3. 手机上传前、上传中、上传成功。
4. 手机相册与投票。
5. 手机作品详情。
6. 管理概览。
7. 管理账号配置。
8. 管理实时排名。
9. 大屏排名展示。

## 11. 待确认交互问题

1. 相册是否默认展示上传人姓名，还是只展示作品编号？
2. 用户是否需要复制或分享自己的作品编号？
3. 投票按钮是否坚持“上下箭头”视觉，还是使用更明确的“投票”按钮并保留箭头图标？
4. 手机端相册是否优先双列瀑布流，还是单列大图？
5. 大屏展示更偏“排名榜”还是“作品墙”？
6. 管理员是否需要手动代用户上传或删除作品？
7. 活动结束后是否需要生成可下载结果页或 Excel？

1. 带上作品上传人的工号
2. 允许生成一个自己作品的分享页面给他人，其他有权限的人可以点开投票
3. 可以有一个投票，然后默认1票，通过上下箭头调整票数
4. 手机端可以默认双列瀑布流
5. 大屏展示相册状态可以是作品墙，进入排名展示模式时候用排行榜
6. 管理员可以人工删除他人的作品
7. 不用下载
